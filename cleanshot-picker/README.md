# CleanShot Picker

웹페이지를 **클릭으로 정리한 뒤** 현재 보이는 화면이나 페이지 전체를 PNG로 저장하는 Chrome 확장입니다.
지우기 · 이동 · 크기 · 텍스트 · 가리기 다섯 도구로 정리하고, 영역 도구로 찍을 부분만 고르고, 강조·스포트라이트·화살표·번호·글상자로 표시를 더할 수 있습니다. 그려 넣은 것은 눌러서 옮기거나 크기를 바꿀 수 있습니다. 저장이 끝나면 건드린 것은 전부 원래대로 돌아옵니다.
쿠키 배너·채팅 버튼·앱 설치 배너·공지 팝업은 `Q` 한 번에 숨기고, 사이트마다 늘 하는 정리는 레시피로 저장해 두면 다음에 켤 때 바로 적용됩니다.

원본 DOM 구조는 건드리지 않습니다. 모든 변경은 인라인 스타일 한 줄이거나 오버레이 위의 박스라서
닫기만 하면(정리한 것이 있으면 실수 방지로 `Esc` 두 번) 페이지가 손상 없이 복구됩니다. 텍스트 도구로 고친 글자는 원래 노드 객체를 그대로 제자리에
돌려놓는 방식으로 되돌리므로, 페이지의 이벤트 리스너나 React 같은 프레임워크가 쥔 참조도 끊기지 않습니다.

## 설치

1. `cleanshot-picker.zip` 을 압축 해제합니다. 푸는 위치는 상관없지만 **나중에 지우지 않을 곳**에 두세요. 크롬이 이 폴더를 계속 참조합니다.
2. Chrome 주소창에 `chrome://extensions` 를 입력해 엽니다.
3. 오른쪽 위 **개발자 모드**를 켭니다.
4. **압축해제된 확장 프로그램을 로드**를 누르고 `manifest.json` 이 들어 있는 `cleanshot-picker` 폴더를 선택합니다. 파일이 아니라 폴더를 골라야 합니다.
5. 툴바 퍼즐 아이콘에서 핀으로 고정해 두면 편합니다.

설치 직후에는 **이미 열려 있던 탭을 한 번 새로고침**해야 합니다.

> 확장 프로그램 ID 는 `fdhmaehlpgpegiemhcfhffecnendgibe` 로 고정되어 있어, 어느 PC·어느 폴더에 설치해도 같습니다. 새 버전은 **같은 폴더에 덮어쓰고 `chrome://extensions` 에서 새로고침(⟳)** 하면 됩니다.

### 1.0.1 이하에서 업데이트할 때 (확장 ID 가 바뀝니다)

1.1.0 부터 확장 ID 를 고정했습니다. 그 전 버전은 설치한 폴더 위치로 ID 가 정해졌기 때문에, 새 버전은 다른 확장으로 인식됩니다. 이 확장이 저장하는 것은 빈자리 남김/제거와 툴바 위치 두 가지 설정뿐이라 따로 옮길 데이터는 없습니다.

1. `chrome://extensions` 에서 기존 CleanShot Picker 를 먼저 **삭제**합니다. 두 개를 함께 두면 `Alt+Shift+S` 단축키가 겹쳐 새 버전에 걸리지 않을 수 있습니다.
2. 새 버전 폴더를 위 4번처럼 로드하고, 열려 있던 탭을 새로고침합니다.
3. 빈자리 제거·툴바 위치나 단축키(`chrome://extensions/shortcuts`)를 바꿔 썼다면 다시 설정합니다.

### 요소·영역만 찍기

영역 도구(`6`)로 **요소를 누르면 그 요소**, **Shift+드래그(또는 빈 곳 드래그)하면 그 사각형**을 찍을 부분으로 고릅니다. 고른 곳은 점선 테두리로, 바깥은 어둡게 보입니다(이 표시는 찍히지 않습니다). 그다음 `Enter`(또는 **캡처**)는 그 부분만 `…-area.png` 로 저장하고, `C`(또는 **복사**)는 그 부분만 클립보드에 넣습니다.

- 가리기는 화면 전체에 칠한 뒤에 잘라 내므로, 고른 부분에 걸친 가리기도 그대로 들어갑니다.
- 고른 요소는 스크롤·레이아웃이 바뀌어도 따라갑니다(가리기 박스와 같은 방식). 다시 고르면 바뀌고, `Ctrl+Z`·**전체 복원**으로 없앱니다.
- 보이는 화면만 찍습니다. 고른 부분이 화면 밖으로 나가 있으면 보이는 부분만 저장하고 "화면 밖 부분은 빠졌습니다"라고 알립니다. 전혀 보이지 않으면 찍지 않습니다. 페이지 전체 캡처(`Shift+Enter`)에는 영역을 쓰지 않습니다.

### 주석

찍은 그림에 남는 표시입니다. 그린 곳의 페이지 요소에 붙어 스크롤·레이아웃이 바뀌어도 따라갑니다. `Ctrl+Z`·**전체 복원**으로 없앱니다.

- **강조**(`7`): 빨간 테두리. 가리기처럼 요소를 누르거나 Shift+드래그(또는 빈 곳 드래그)로 고릅니다. 요소를 누르면 내용을 가리지 않게 요소 바깥으로 3px 띄워 그립니다. 여러 개 둘 수 있습니다.
- **스포트라이트**(`8`): 고른 곳만 밝게 두고 바깥을 어둡게 합니다. 고르는 방법은 강조와 같고, 하나만 두며 다시 고르면 바뀝니다.
- **화살표**(`9`): 꼬리에서 머리 쪽으로 끌어 그립니다. 끌지 않고 누르기만 하면 누른 곳을 머리로 하는 화살표를 왼쪽 아래에서(화면 끝이면 반대쪽에서) 놓습니다.
- **번호**(`0`): 누르는 곳마다 빨간 원에 1, 2, 3… 을 붙입니다. 다음 번호는 남아 있는 번호 가운데 가장 큰 것 다음입니다.
- **글상자**(`T`): 누른 곳에 바로 씁니다. `Enter`·`Esc`·바깥 클릭으로 끝내고, `Shift+Enter` 는 줄바꿈입니다. 한글을 조합하는 도중에 누른 `Enter` 는 끝내기로 보지 않습니다(조합 중인 글자를 지키려고). 아무것도 쓰지 않으면 없어집니다. 쓰는 동안 누른 키는 페이지의 단축키로 가지 않습니다.
- 보이는 화면 캡처·복사·영역 캡처·**페이지 전체 캡처**에 모두 들어갑니다. 페이지 전체를 찍을 때는 장마다 그 자리에 그려져 이어 붙고, 머리글처럼 화면에 붙은 요소 안에 그린 것은 그 요소와 함께 한 번만 나옵니다. 스포트라이트는 구멍이 없는 장도 어둡게 합니다.
- 가리기는 주석보다 위에 칠해집니다. 가린 자리에 겹친 주석은 저장된 그림에서도 가려집니다(화면에서도 그렇게 보입니다).

### 그린 것 옮기기·크기 바꾸기

가리기(`5`)·영역(`6`)·강조(`7`)·스포트라이트(`8`)·화살표(`9`)·번호(`0`)·글상자(`T`)로 그린 것은 **그 도구일 때** 다룰 수 있습니다. 포인터를 올리면 얇은 파란 테두리와 이동 커서로 잡을 수 있다고 알려 줍니다.

- **고르기·옮기기**: 그린 것을 누르면 골라지고(파란 점선), 누른 채 끌면 옮겨집니다. 테두리만 있는 강조·스포트라이트·영역은 **테두리 근처**를 눌러야 잡힙니다 — 안쪽을 누르면 지금처럼 그 안의 요소를 고릅니다. `Shift` 를 누른 채 끌면 잡지 않고 새로 그립니다.
- **크기**: 고른 가리기·영역·강조·스포트라이트는 8방향 핸들로, 화살표는 두 끝의 둥근 핸들로 바꿉니다. 모서리 핸들을 `Shift` 와 함께 끌면 가로세로 비율을 지킵니다. 번호와 글상자는 옮기기만 합니다.
- **글 고치기**: 골라 둔 글상자를 한 번 더 누르면 글을 고칩니다.
- **키**: 방향키로 1px(`Shift` 10px)씩 옮기고, `Delete` 로 지웁니다. `Esc` 는 고르기만 풀고, 한 번 더 누르면 평소처럼 나갑니다.
- 옮기거나 크기를 바꾼 것은 새 자리를 통째로 품는 요소에 다시 붙어 따라갑니다. 요소를 감싸던 가리기·강조도 그때부터는 그 자리와 크기를 지킵니다(요소 크기가 바뀌어도 따라 바뀌지 않습니다).
- 옮기기·크기·지우기·글 고치기는 모두 `Ctrl+Z` 로 하나씩 되돌립니다. 이어서 누른 방향키는 한 번에 되돌립니다.

### 클립보드에 복사

`C`(툴바 **복사**)를 누르면 보이는 화면을 찍어 가리기까지 칠한 PNG 를 클립보드에 넣습니다. 파일은 만들지 않고, 저장할 때처럼 전체 복원 후 닫힙니다. 메신저·메일·문서에 바로 붙여 넣을 수 있습니다.

- 새 권한은 없습니다. 브라우저의 클립보드 API(`navigator.clipboard.write`)를 씁니다.
- 브라우저는 **https 페이지**(그리고 `localhost`·`127.0.0.1`)에서만 클립보드 쓰기를 허용합니다. `http://` 사내 시스템처럼 막히는 페이지나, 사이트 설정에서 클립보드를 막았거나 탭에 포커스가 없을 때는 복사하지 못한 이유를 알리고 **정리한 상태를 그대로 둡니다**. 그때는 `Enter` 로 파일로 저장하세요.
- 페이지 전체 캡처는 아직 파일로만 저장합니다.

### 저장 설정

툴바의 **설정**(또는 `chrome://extensions` 의 확장 **세부정보 → 확장 프로그램 옵션**)에서 고릅니다. 바꾸면 바로 저장되고 다음 캡처부터 쓰이며, 같은 Chrome 계정으로 동기화됩니다. 기본값은 예전과 같습니다(PNG, 화면 그대로, `cleanshot/도메인-날짜-시간`).

| 설정 | 고를 수 있는 것 | 알아 둘 것 |
| --- | --- | --- |
| 저장 형식 | PNG · JPEG · WebP | JPEG·WebP 는 품질 0.92. 가리기는 형식으로 바꾸기 전에 칠하므로 어느 형식이든 원본 픽셀이 남지 않습니다 |
| 크기 | 화면 그대로 · 1배 · 2배 | 화면 그대로는 장치 픽셀(고해상도 화면에서는 커짐), 1배는 웹페이지의 CSS 픽셀 크기, 2배는 그 두 배. 화면이 1배율이면 2배는 늘려서 저장하므로 더 또렷해지지는 않습니다 |
| 파일 이름 | 양식. 칸 `{host}` 도메인 · `{title}` 페이지 제목 · `{date}` 날짜 · `{time}` 시각 | `/` 로 폴더를 나눕니다(다운로드 폴더 밖으로는 못 나감). 끝의 `-full`·`-area` 와 확장자는 붙여 줍니다. 파일 이름에 쓸 수 없는 글자와 제목 속 `/` 는 `_` 로 바뀌고, `CON`·`NUL` 같은 이름은 앞에 `_` 가 붙습니다. 칸 하나는 80자, 경로 전체는 180자까지 |
| 저장할 때마다 위치 묻기 | 켬 · 끔 | 저장 위치 창을 띄웁니다. 창을 닫으면 저장하지 않고 정리한 상태를 그대로 둡니다 |
| 주소·시각 표시 | 켬 · 끔 | 그림 아래에 띠를 덧붙여 페이지 주소와 찍은 시각(시간대 포함)을 적습니다. 그림은 가리지 않습니다. 주소의 `?` 뒤(검색어)와 `#` 뒤는 로그인 토큰·개인정보가 자주 들어가므로 넣지 않고, 로컬 파일은 폴더 경로 없이 파일 이름만 적습니다 |
| 스크롤 막대 빼기 | **켬**(기본) · 끔 | 보이는 화면을 찍을 때 페이지의 스크롤 막대 자리를 잘라 내고 저장합니다(레이아웃은 바꾸지 않으므로 가리기가 어긋나지 않습니다). 페이지 전체 캡처에는 원래 들어가지 않습니다. 페이지 안쪽 스크롤 영역의 막대는 그대로입니다 |
| 이어서 찍기 | 켬 · **끔**(기본) | 툴바의 **찍고 닫기 ↔ 찍고 계속** 과 같은 값입니다 — 아래 [이어서 찍기·페이지 조작](#이어서-찍기페이지-조작) |

- 크기와 주소·시각 띠는 보이는 화면·영역·전체 페이지·클립보드 복사에 모두 적용됩니다. **클립보드 복사는 형식과 상관없이 PNG** 입니다(브라우저 클립보드가 PNG 만 받습니다).
- 크기를 바꾸거나 띠를 붙인 그림이 한 변 32,767px·넓이 약 6,700만 px 를 넘으면 들어가게 줄여 저장하고 몇 배로 저장했는지 알립니다.
- 브라우저가 고른 형식으로 그림을 만들지 못하면 PNG 로 저장하고 알립니다.

### 이어서 찍기·페이지 조작

- **찍고 계속**: 툴바의 **찍고 닫기** 단추를 누르면 **찍고 계속** 으로 바뀌고(설정에 남습니다), 저장·복사한 뒤에도 정리한 상태를 그대로 둬서 스크롤하거나 영역을 바꿔 이어서 찍을 수 있습니다. 다 찍으면 `Esc` 두 번이나 **닫기**로 모두 되돌리고 나갑니다.
- **Esc 실수 방지**: 정리한 것이 있을 때 `Esc` 를 한 번 누르면 "작업 N개를 모두 되돌리고 닫으려면 Esc 를 한 번 더" 라고만 알리고 그대로 둡니다. 2.5초 안에 한 번 더 눌러야 나갑니다. 쓰기·고르기를 끝내려고 누른 `Esc` 가 작업을 날리지 않게 하려는 것입니다. 정리한 것이 없으면 한 번에 나갑니다. **닫기** 단추와 아이콘(`Alt+Shift+S`)은 바로 닫습니다.
- **페이지 조작(`Space` 를 누르는 동안)**: 누르고 있는 동안은 클릭이 페이지로 가서, 드롭다운·메뉴·탭·펼치기 단추를 직접 열 수 있습니다. 요소 강조와 도구 커서는 꺼지고(페이지 커서가 보입니다), 막아 두었던 다른 출처 iframe 도 그동안은 누를 수 있습니다. 떼면 다시 고르기로 돌아오고, 연 상태 그대로 `Enter`·`C` 로 찍습니다. 이 키들은 페이지로 가지 않으므로 바깥을 누르면 닫히는 메뉴도 열린 채 찍힙니다(툴바 단추를 누르면 그 메뉴가 닫힐 수 있습니다). 마우스를 올리면 열리는 메뉴는 원래도 열립니다.
  - 페이지 조작 중에 링크를 누르면 페이지가 바뀌어 정리한 것이 사라집니다.
  - iframe 안을 누르거나 창이 포커스를 잃으면 페이지 조작이 끝납니다(떼는 키를 받지 못할 수 있어서).

### 한 번에 정리

`Q`(툴바 **정리**)를 누르면 찍을 때 방해되는 것을 찾아 한꺼번에 숨깁니다. 숨긴 것은 작업 하나라 `Ctrl+Z` 한 번에 모두 돌아오고, 알림에 무엇을 몇 개 숨겼는지 나옵니다.

| 분류 | 찾는 방법 |
| --- | --- |
| 쿠키 배너 | 널리 쓰는 동의 관리 도구(OneTrust, Cookiebot, Usercentrics, Didomi, Quantcast, TrustArc, CookieYes 등)가 만드는 요소. 또는 화면에 떠 있거나(fixed·sticky) 문서 맨 위에서 내용을 밀어내는 띠 가운데, 쿠키 안내 문장(또는 consent·gdpr 같은 이름)과 동의·닫기 같은 단추가 함께 있는 것 |
| 채팅 버튼 | 채널톡·Intercom·Zendesk·HubSpot·LiveChat·tawk.to 등이 만드는 요소. 또는 화면 아래쪽에 떠 있는 작은 요소 가운데 이름·글자·안쪽 iframe 에 채팅·상담·문의 같은 말이 있는 것 (열린 채팅 창 포함) |
| 앱 설치 배너 | Smart App Banner·Branch 배너. 또는 화면 위·아래 끝의 넓고 낮은 띠 가운데 "앱에서 보기"·"앱 설치"·"Open in app" 같은 말이 있고 단추가 몇 개뿐인 것 |
| 공지 팝업 | "오늘 하루 보지 않기"·"7일간 보지 않기"·"다시 보지 않기"·"Don't show again" 글이 든 띄운 요소(fixed, 또는 화면보다 작은 absolute) 가운데 팝업 전체. 팝업이나 쿠키 창을 숨길 때는 그 뒤에 화면을 다 덮고 깔린 반투명 가림막도 함께 숨깁니다 |

- 틀리게 숨기는 것보다 놓치는 쪽을 택했습니다. 메뉴의 "쿠키 설정"·"앱 다운로드" 링크, 바닥글의 쿠키 정책 링크, 화면 높이만 한 옆 메뉴, 맨 위로 단추, 본문 문단은 숨기지 않습니다. 놓친 것은 지우기(`1`)로 지우세요.
- 숨기는 방식은 설정과 상관없이 늘 빈자리까지 지우기(`display: none`)입니다.
- 문서와 그 안의 shadow DOM 을 봅니다. 같은 출처 iframe 안은 보지 않습니다(iframe 으로 뜨는 채팅 위젯은 iframe 째 숨깁니다).
- 이미 숨긴 것은 다시 찾지 않으므로, 늦게 뜬 배너는 `Q` 를 한 번 더 누르면 됩니다. 더 숨길 것이 없으면 그렇게 알립니다.
- 모달 `<dialog>` 로 뜬 창은 툴바가 그 안에 붙어 있어서 숨기지 않습니다(숨기면 툴바까지 사라집니다).
- 설정 화면의 **선택 모드를 켤 때 바로 정리**를 켜면 켤 때마다 정리합니다(기본 끔). 그때도 `Ctrl+Z` 한 번이면 그때만 뺍니다.

### 사이트별 레시피

툴바의 **레시피 저장**을 누르면 이 사이트(도메인)에서 한 정리를 저장해 두고, 다음에 그 사이트에서 선택 모드를 켜면 바로 적용합니다. 적용한 것도 작업 하나라 `Ctrl+Z` 한 번이면 그때만 빠집니다.

- **저장하는 것**: 지운 것(`1`, 빈자리 남김·제거 방식 그대로), 요소째 가린 것(`5` 로 요소를 누른 것), 고쳐 쓴 글(`4`), 한 번에 정리를 썼는지. 같은 출처 iframe 과 shadow DOM(닫힌 것 포함) 안의 요소도 됩니다.
- **넣지 않는 것**: 드래그로 그리거나 옮긴 가리기, 이동·크기, 영역, 주석(강조·화살표 등). 그때 화면의 자리라 다음에는 맞지 않기 때문입니다. 저장 알림에 넣지 않은 개수가 나옵니다.
- **사이트**는 도메인입니다(포트 포함, 앞의 `www.` 는 뺌). 같은 사이트의 다른 페이지에서도 적용하고, 그 페이지에 없는 요소는 건너뛴 뒤 "못 찾음 N" 으로 알립니다. 로컬 파일(`file://`)은 모두 한 사이트로 봅니다.
- 저장할 때마다 그 사이트 레시피에 더해집니다. 같은 요소의 글을 다시 고쳐 저장하면 새 글로 바뀝니다. 항목을 빼려면 설정 화면에서 지웁니다.
- 요소는 다음에도 찾을 수 있게 사람이 붙인 이름(id·`data-testid`·클래스·`name`)으로 기억하고, 그런 이름이 없으면 위 요소부터의 순서(`:nth-of-type`)로 기억합니다. 화면 틀이 그때그때 만든 이름(`ember123`·`css-1x2y3z`·`:r1:` 같은 것)과 상태 클래스(`active`·`open` 등)는 쓰지 않습니다. 선택자에 맞는 요소가 여럿이면 모두에 적용합니다(항목마다 50개까지).
- **개인정보**: 페이지의 글자는 저장하지 않습니다. 선택자, 이름표(`태그#id.클래스`), 직접 고쳐 쓴 글만 이 PC 의 `chrome.storage.local` 에 남고 동기화되지 않습니다.
- 설정 화면의 **사이트별 레시피**에서 사이트마다 켜기·끄기, 정리 포함, 항목 하나씩 지우기, 사이트째 지우기(두 번 눌러야)를 합니다. 끈 레시피는 적용하지 않고, 그 사이트에서 다시 저장하면 켜집니다.
- 툴바를 품은 요소(열려 있는 모달 `<dialog>`)를 지우는 항목은 건너뜁니다.
- 한도: 사이트 300개(넘으면 오래전에 저장한 사이트부터 빠짐), 사이트마다 항목 200개.

downloads API가 실패하면(정책으로 막힌 경우 등) 페이지에서 일반 다운로드로 한 번 더 저장하고
"브라우저 다운로드로 저장했습니다"라고 알립니다. 이때는 하위 폴더 없이 `도메인-날짜-시간.png` 로 저장됩니다.
같은 탭에서 대체 저장을 거듭하면 크롬의 자동 다운로드 제한에 걸릴 수 있습니다.

## 전체 페이지 캡처

`Shift+Enter`(툴바 **전체**)를 누르면 맨 위부터 한 화면씩 내려가며 찍어 한 장의 그림으로 잇습니다(형식·크기는 [저장 설정](#저장-설정)대로). 정리한 내용과 가리기는 페이지 전체에 그대로 적용됩니다.

- **찍는 동안**: 확장 UI는 사라지고, 커서가 기다림 모양으로 바뀌며, 툴바 아이콘 배지에 진행률(%)이 뜹니다. 휠 스크롤은 막힙니다. 한 화면에 약 0.6초가 걸리는데, 크롬이 확장의 화면 캡처를 초당 2회로 제한하기 때문입니다.
- **멈추기**: `Esc`(또는 확장 아이콘·`Alt+Shift+S`)를 누르면 저장하지 않고 멈춥니다. 정리한 것은 그대로 남아 다시 찍을 수 있습니다.
- **끝나면**: 찍느라 바꾼 스타일과 스크롤 위치를 원래대로 돌려놓습니다. 저장하면 보이는 화면 캡처와 같이 전체 복원 후 닫힙니다.
- **화면에 붙은 요소(fixed)**: 머리글처럼 화면 위쪽에 붙은 요소는 첫 장에만, 바닥글·채팅 버튼처럼 아래쪽에 붙은 요소는 마지막 장에만 남깁니다. 그래서 이어 붙인 이미지에 장마다 되풀이되지 않습니다. 그 요소 안의 가리기 박스도 같은 장에만 칠합니다. 화면을 거의 다 덮는 요소(배경, 앱 틀)는 그대로 두고, `transform` 이 걸린 조상 안에 있어 내용과 함께 움직이는 fixed 요소도 그대로 둡니다(한 번 내려 봐서 가립니다).
- **sticky 요소**: 찍는 동안 제자리(`position: relative`)에 둬서 원래 자리에 한 번만 나옵니다.
- **가리기**: 장마다 그때의 박스 위치를 다시 재서 서비스 워커가 PNG에 칠합니다. 화면의 박스 레이어는 찍는 동안 숨깁니다. 박스 위치를 재지 못하면 저장하지 않습니다.
- **주석**: 강조·스포트라이트·화살표·번호·글상자는 장마다 그 스크롤 위치에 그려진 채 찍혀 함께 이어 붙습니다. 장의 경계에 걸친 강조도 경계에 줄이 생기지 않습니다. 화면에 붙은 요소 안에 그린 것은 그 요소가 나오는 장에만, 안쪽 스크롤 영역을 찍을 때 그 영역 밖에 그린 것은 첫 장에만 나옵니다.
- **안쪽 영역만 스크롤되는 화면**: 관리 화면처럼 문서는 그대로이고 안쪽 영역만 스크롤되면, 화면 넓이의 1/4 이상인 가장 큰 스크롤 영역을 골라 **그 영역의 내용 전체**를 저장합니다. 머리글·옆 메뉴는 빠집니다. 스크롤할 내용이 없으면 보이는 화면을 저장하고 그렇게 알립니다.
- **다른 탭으로 바꾸면**: 찍기 직전과 직후마다 이 탭이 아직 활성 탭인지 확인합니다. 그사이 다른 탭으로 바꾸면 그 탭 화면이 섞이지 않게 멈추고 저장하지 않습니다.
- **아주 긴 페이지**: 이미지 한 변 32,767px, 넓이 약 6,700만 px(메모리 256MB)까지 담습니다. 넘으면 위에서부터 그만큼만 저장하고 "너무 길어 위에서 …px 까지만"이라고 알립니다. 너비 1,250 CSS px 화면이면 1배율에서 약 3만 2천 CSS px, 2배율에서 약 1만 3천 CSS px까지입니다.
- 화면 안 이미지는 장마다 다 받아질 때까지 최대 1.2초 기다립니다. 스크롤 스냅과 스크롤 앵커링은 찍는 동안 끕니다(요청한 자리와 다른 곳에 멈추면 이음매가 어긋나기 때문).
- 새 권한은 없습니다. 아이콘을 누를 때 받는 `activeTab` 으로 찍습니다.

## 알아두면 좋은 것

**빈자리 남김 / 빈자리 제거** — 툴바 첫 버튼입니다. 기본은 `visibility: hidden` 이라 요소가 차지하던 공간이 남고 주변이 흔들리지 않습니다. 배너처럼 빈칸이 어색하면 **빈자리 제거**(`display: none`)로 바꾸세요. `position` 이 `fixed`·`sticky`·`absolute` 인 요소는 어차피 문서 흐름 밖이라 설정과 무관하게 항상 공간까지 제거합니다.

**툴바가 가리는 요소** — 툴바는 화면 아래 가운데에 있어 쿠키 배너 자리와 겹칩니다. `Tab` 으로 위로 옮기세요.

**가리기** — 요소를 클릭하면 그 요소를, `Shift+드래그` 하면 임의 영역을 불투명한 검은 박스로 덮습니다.

- 요소를 가린 박스는 그 요소를 따라갑니다. 고정·sticky 요소를 가린 뒤 스크롤하거나, 빈자리 제거로 레이아웃이 밀리거나, 내부 스크롤 영역을 굴리거나, 이동·크기 도구로 요소를 바꿔도 박스가 요소 위에 있습니다.
- 영역 박스는 그 영역을 통째로 품는 가장 안쪽 요소에 붙어 함께 움직입니다. 그 요소가 스크롤 영역이면 내용과 함께 움직입니다. 여러 요소에 걸쳐 품는 요소가 없으면 문서 좌표에 붙어 페이지와 함께 스크롤됩니다.
- 스크롤 영역이나 iframe 밖으로 나간 부분은 잘라서 그립니다. 가린 요소를 지워서(`display: none`) 보이지 않게 되면 박스도 숨기고, 되돌리면 다시 나타납니다. 페이지가 요소를 DOM에서 떼어 내면 박스는 마지막 자리에 남습니다.
- 캡처할 때는 박스 위치를 서비스 워커로 보내 PNG에 한 번 더 직접 칠합니다. 화면의 박스가 다른 요소 아래에 깔리더라도 저장되는 이미지에는 검정이 반드시 들어갑니다. 칠하지 못하면 저장하지 않고 실패를 알립니다.

방식은 검정 하나뿐입니다. 고를 것이 없는 편이 안전하기 때문입니다. 모자이크나 블러는 원본 픽셀을 완전히 버리지 않아서, 계좌번호처럼 되살아나면 곤란한 것을 가릴 때 쓰면 위험합니다. 검은 박스는 그 자리의 픽셀을 통째로 덮어쓰므로 저장된 PNG에 원본이 남지 않습니다.

**dialog·popover 위에서** — 툴바와 박스는 popover로 띄워 최상단(top layer)에 올리므로, `showModal()`로 연 `<dialog>`나 popover 위에도 그려집니다. 모달 dialog가 열려 있으면 그 바깥은 브라우저가 클릭을 막으므로(inert) 툴바를 그 dialog 안에 붙이고, dialog가 닫히면 원래 자리로 돌려놓습니다.

**iframe과 shadow DOM** — open·closed shadow DOM 안의 요소와 같은 출처 iframe 안의 요소도 고를 수 있습니다. iframe 안 맨 위 요소에서 `↑` 를 누르면 iframe 자체가 잡힙니다. 다른 출처 iframe(광고 등)은 안을 볼 수 없으므로 iframe 위 아무 곳이나 가리키면 iframe 전체가 하나의 요소로 잡힙니다. 선택 모드 동안은 이런 iframe에 `pointer-events: none` 을 걸어 클릭이 iframe 안으로 새지 않게 하므로, 그동안은 그 iframe 안을 스크롤할 수 없습니다. 닫으면 원래대로 돌아옵니다.

**크기 조절이 안 먹을 때** — flex·grid 자식은 부모의 규칙이 이기므로 `flex: 0 0 auto` / `grid-area: auto` 를 자동으로 같이 겁니다. 그래도 안 되면 `↑` 로 부모를 잡아 조절해 보세요.

**켜고 찍는 속도** — 아이콘을 눌러 툴바가 뜨기까지 같은 탭에서 두 번째부터는 15~25ms입니다. `Enter` 를 누르고 저장될 때까지는 60~90ms였습니다(스크롤 막대 빼기를 넣기 전, 1배율. 아래 참고).

가리기 박스가 있으면 PNG에 박스를 직접 칠하는 단계가 더해집니다. 헤드리스 Chromium 131에서 잰 서비스 워커 처리 시간(캡처부터 저장 요청까지)은 1264×805 화면에서 박스가 없을 때 37~62ms, 있을 때 63~111ms였고, 2배율 화면(2534×1614)에서는 124~190ms와 206~272ms였습니다. 브라우저를 띄운 뒤 첫 캡처는 이보다 느렸습니다(박스 1개, 1배율 약 170ms, 2배율 약 550ms).

[저장 설정](#저장-설정)의 **스크롤 막대 빼기**(기본으로 켬)는 찍은 PNG 를 잘라 다시 만들어야 하므로, 다른 손볼 것이 없는 캡처도 그만큼 느려집니다. 같은 세션에서 켬·끔을 번갈아 6번씩 잰 가운데값은 1배율 130ms 대 66ms, 2배율 396ms 대 208ms 였습니다(약 +60ms, +190ms). 가리기·영역·형식·크기·띠 가운데 하나라도 쓰면 어차피 다시 만드므로 차이가 거의 없습니다. 속도가 더 중요하면 설정에서 끄세요.

전체 페이지 캡처는 `Shift+Enter` 뒤 0.7초 동안 안내를 보여 준 다음 찍기 시작합니다. 요소 2만 7,500개짜리 표 페이지에서 찍기 전 준비(스크롤 대상·fixed·sticky 요소 찾기)는 약 40ms였고, 그 뒤 한 장에 0.55~0.65초가 걸렸습니다. 4,030px 문서(1배율, 6장)는 누른 뒤 저장까지 약 4.3초였습니다.

크롬은 MV3 확장의 백그라운드 워커를 30초쯤 놀면 종료하는데, 그러면 아이콘을 눌렀을 때 워커가 다시 뜨기를 기다리느라 툴바가 늦게 나타납니다. 이 확장은 30초짜리 알람으로 워커를 계속 깨워 둬서 첫 클릭도 기다림 없이 뜹니다. 대가는 확장을 쓰지 않는 동안에도 30초마다 워커가 잠깐 깨어난다는 것입니다(한 번에 수 밀리초). 선택 모드가 열려 있는 동안과 닫은 뒤 5분간은 페이지 쪽에서도 20초마다 워커를 깨워 둡니다.

## 알려진 제약

- **다른 출처(cross-origin) iframe** 안의 개별 요소는 집을 수 없습니다. iframe 전체를 통째로 지우거나 가리세요. 광고는 대부분 이걸로 해결됩니다.
- iframe에 CSS `transform`(확대·회전)이 걸려 있으면 그 안 요소의 강조 상자와 가리기 박스 위치가 어긋날 수 있습니다.
- shadow DOM 안에 들어 있는 다른 출처 iframe은 위의 `pointer-events` 처리를 하지 않아, iframe 전체를 고르기 어렵고 클릭이 그 안으로 샐 수 있습니다.
- `chrome://`, 웹스토어, 다른 확장 페이지에는 주입할 수 없습니다. 아이콘에 `✕` 배지가 잠깐 뜹니다.
- 저장되는 이미지는 기본으로 CSS 픽셀이 아니라 **장치 픽셀** 크기입니다. 고해상도 화면에서는 눈에 보이는 것보다 큰 이미지가 나옵니다. 설정의 **크기**를 1배로 두면 CSS 픽셀 크기로 저장합니다.
- 전체 페이지를 1배로 저장해도, 너무 긴 페이지를 자르는 한도는 찍힌 화면의 배율(장치 픽셀)로 계산합니다. 크기는 다 이어 붙인 뒤에 바꾸기 때문입니다.
- 저장 위치 창은 헤드리스 시험에서 바로 닫히는 경우(저장하지 않음)만 확인했습니다. 실제 창에서 위치를 고르는 경우는 같은 기다리기(다운로드 파일 위치가 정해지는 것)를 창 없이 확인했습니다.
- 텍스트 편집은 React 같은 프레임워크가 리렌더하면 되돌아갈 수 있습니다. 대개 캡처는 몇 초 안에 끝나므로 실제 문제가 되는 일은 드뭅니다.
- 한 번에 정리와 레시피는 페이지 구조에 기댑니다. 사이트가 바뀌면 놓치거나(레시피는 "못 찾음" 으로 알림) 드물게 다른 요소에 맞을 수 있으니, 찍기 전에 화면을 한 번 보세요. 레시피는 선택 모드를 켤 때 한 번 적용하므로 켠 뒤에 생긴 요소에는 적용되지 않습니다(`Q` 정리는 다시 누를 수 있습니다). 고쳐 쓴 글을 다시 넣을 때 줄바꿈은 빈칸으로 보입니다.
- 전체 페이지 캡처의 제약
  - 가로로는 지금 보이는 너비만 찍습니다. 화면보다 넓은 페이지의 오른쪽은 빠집니다.
  - 시작할 때의 페이지 높이까지만 찍습니다. 끝없이 이어지는 목록처럼 내려가면서 길어지는 부분은 빠집니다.
  - 내려가는 동안 위쪽 내용이 바뀌는 페이지(늦게 받아지는 이미지가 위쪽 높이를 바꾸는 경우 등)는 이음매가 어긋날 수 있습니다. 한 번 끝까지 스크롤해 둔 뒤 찍으면 대개 해결됩니다.
  - 움직이는 요소(동영상, 애니메이션, 스크롤에 따라 나타나는 효과)는 장마다 다른 순간이 찍힙니다.
  - 안쪽 스크롤 영역을 찍을 때는 그 영역 위에 떠 있는 fixed 요소만 정리합니다. 영역을 덮는 다른 요소(absolute 로 띄운 창 등)는 장마다 되풀이될 수 있습니다.
  - 같은 출처 iframe 안의 fixed·sticky 요소는 따로 정리하지 않습니다.
  - 찍는 사이 다른 탭으로 바꾸면 멈춥니다. 다만 그 탭이 숨겨진 동안에는 페이지 쪽 진행도 멈춰 있다가, 돌아오면 이어서 찍을 수 있습니다(그때도 다른 탭 화면은 섞이지 않습니다).

## 파일 구성

```
cleanshot-picker/
├── manifest.json     권한과 진입점 선언 (MV3)
├── background.js     service worker — 주입, 캡처, 전체 페이지 잇기, 가리기 박스 칠하기, 크기·띠·형식 마무리, 저장
├── picker.js         content script — 오버레이, 열한 도구, 그린 것 고르기·옮기기, 작업 스택, 전체 페이지 스크롤, 한 번에 정리·레시피 적용과 저장
├── settings.js       저장 설정의 기본값·파일 이름 양식·띠 글 (service worker 와 설정 화면이 함께 씀)
├── recipes.js        한 번에 정리의 판정·내장 목록, 사이트별 레시피 저장값 (피커와 설정 화면이 함께 씀)
├── options.html      설정 화면 (툴바의 "설정", 확장 프로그램 옵션)
├── options.js        설정 화면 동작 — 바꾸면 바로 storage.sync 에 저장, 사이트별 레시피 목록(storage.local)
├── shared/
│   └── redact-core.js  공용 가리기 코어 — 화면 좌표·잘린 부분 계산, 검정 칠하기 (ClickGuide 와 같은 파일)
├── icons/            16 / 32 / 48 / 128 px
└── README.md
```

`picker.js` 의 오버레이는 closed shadow DOM 안에서 아래부터 **주석 레이어**, **마스크 레이어**, **UI 레이어**로 나뉩니다.
closed 라서 페이지 스크립트가 툴바 버튼에 손댈 수 없고, popover 로 띄워 top layer 에 올라갑니다.
캡처 직전 `.capturing` 클래스로 UI 레이어(툴바·고른 표시·핸들)만 숨기므로 주석과 가리기 박스는 사진에 남고 툴바는 빠집니다.
그와 별도로 `background.js` 가 가리기 사각형을 PNG 에 직접 칠합니다.

`shared/redact-core.js` 는 ClickGuide 와 함께 쓰는 공용 모듈입니다. 원본은 저장소 최상위 `shared/` 에 있고,
고친 뒤 `node scripts/sync-shared.mjs` 로 이 폴더에 복사합니다(사본을 직접 고치지 않습니다).
피커를 주입할 때 이 파일을 먼저 싣고, `background.js` 도 `importScripts` 로 불러옵니다.

되돌리기는 종류별 목록이 아니라 **하나의 작업 스택**입니다. 각 작업이 자기 복원 함수를 들고 있어
`Ctrl+Z` 는 무엇이 마지막이었는지 몰라도 되고, 전체 복원은 스택을 비우는 것과 같습니다.

## 검증

실제 Chromium에 확장을 로드해 54개 항목(기능 38 + 가리기 11 + 워커 깨우기 5)을 통과시켰습니다.

- 지우기: 고정 요소 `display:none` / 흐름 안 `visibility:hidden` 분기, 레이아웃 시프트 없음, 링크 클릭 차단
- 이동: 드래그 이동이 `transform` 으로 적용, 방향키 1px, 연속 방향키가 한 작업으로 묶임, 단계별 되돌리기
- 크기: 핸들 8개 표시, 드래그한 만큼 정확히 변경, flex 자식 `flex: 0 0 auto` 보정, 되돌리기
- 텍스트: `plaintext-only` 진입과 포커스, 타이핑 반영, `Esc` 로 편집만 종료, 원문 복원
- 가리기: 요소 마스크와 영역 마스크가 모두 순수 검정, 방식 전환 버튼이 없음, 대기 없이 19ms 만에 그려짐, 되돌리기, 마스크가 masks 레이어에 있고 `.capturing` 에서도 살아남음, 예전 판이 남긴 설정 키가 치워지고 쓰던 설정은 보존
- 캡처: PNG 저장, 캡처 후 전체 복원과 종료, 재주입 토글
- 속도: 30초 예열 알람이 등록되고 실제로 워커를 깨우는지, 선택 모드가 열려 있는 동안과 닫은 뒤에도 페이지가 워커를 깨우는지, 예열 중에도 선택 모드가 정상인지, 확장 UI를 숨긴 프레임이 합성된 뒤에 찍히는지(툴바가 사진에 새지 않는지)를 3회 반복 확인

결과 이미지도 눈으로 확인했습니다. 가린 계좌번호 줄은 저장된 PNG에서 **색이 한 종류(`#000`)뿐**이라
원본 픽셀이 남아 있지 않고, 툴바는 사진에 새지 않습니다.

가리기 박스 추적, top layer, 텍스트 되돌리기, 대체 저장, iframe·shadow DOM 선택을 고친 뒤에는

- 정리: 페이지에서 `host.shadowRoot` 가 `null`(closed), `Esc`·저장 뒤 인라인 스타일·iframe `pointer-events`·커서 스타일이 모두 원래대로
