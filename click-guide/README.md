# ClickGuide — 클릭 자동 캡처 매뉴얼 생성기

Scribe처럼, **웹에서 하는 클릭과 입력을 자동으로 캡처해 단계별 매뉴얼로 만들어 주는 Chrome 확장**입니다.
녹화 → 자동 설명 생성 → 편집 → HTML / PDF / Markdown 내보내기까지 한 번에 됩니다.

모든 캡처와 가이드는 **이 브라우저 안(IndexedDB)에만** 저장됩니다. 서버로 보내지 않습니다.
(AI 다듬기 기능을 직접 켰을 때만 그 단계의 텍스트가 설정한 API로 전송됩니다.)

---

## 1. 설치 (개발자 모드 로드)

1. 이 폴더를 원하는 위치에 압축 해제합니다.
2. Chrome 주소창에 `chrome://extensions` 입력
3. 오른쪽 위 **개발자 모드** 켜기
4. **압축해제된 확장 프로그램을 로드합니다** 클릭 → `manifest.json`이 들어 있는 이 폴더 선택
5. 툴바 퍼즐 아이콘에서 ClickGuide를 고정해 두면 편합니다.

> Chrome 116 이상이 필요합니다. Edge, Whale 등 Chromium 계열에서도 같은 방식으로 동작합니다.
> 확장 프로그램 ID 는 `aiageoiblanbjihfdogienmgjokgdhil` 로 고정되어 있어, 어느 PC·어느 폴더에 설치해도 같습니다. 새 버전은 **같은 폴더에 덮어쓰고 `chrome://extensions` 에서 새로고침(⟳)** 하면 가이드와 설정이 그대로 유지됩니다.

### 0.1.9 이하에서 업데이트할 때 (확장 ID 가 바뀝니다)

0.2.0 부터 확장 ID 를 고정했습니다. 그 전 버전은 설치한 폴더 위치로 ID 가 정해졌기 때문에, 0.2.0 을 로드하면 새 확장으로 인식되어 그동안 만든 가이드와 설정이 보이지 않습니다. 아래 순서로 옮기세요. 쓰던 가이드가 없다면 바로 0.2.0 을 설치하면 됩니다.

1. 지금 쓰는 ClickGuide 를 **0.1.9 로 업데이트**합니다. 같은 폴더에 덮어쓰고 새로고침하면 ID 가 그대로라 가이드가 유지됩니다. 이미 0.1.9 라면 건너뜁니다.
2. 설정 → 데이터 → **전체 백업 내보내기** 로 ZIP 을 받습니다.
3. 0.2.0 을 **새 폴더**에 풀어 로드합니다. 기존 확장은 아직 지우지 마세요.
4. 새 확장의 설정 → 데이터 → **백업에서 가져오기** 로 받은 ZIP 을 고르고, 가이드가 모두 보이는지 확인합니다. AI 를 쓴다면 API 키는 다시 입력합니다.
5. 확인했으면 기존 확장을 제거합니다.

## 2. 사용법

1. 매뉴얼로 만들 화면을 띄운 탭에서 **확장 아이콘 → 녹화 시작**
2. 평소처럼 클릭하고 입력합니다. 화면 오른쪽 아래에 녹화 표시줄이 뜹니다.
   - 녹화는 시작한 탭과, 녹화 중에 그 탭에서 새로 연 탭에서만 합니다. 다른 탭에는 표시줄이 뜨지 않고 기록되지도 않습니다.
   - 클릭할 때마다 화면 전체를 찍고 클릭한 요소 위치를 기록합니다.
   - 입력칸을 벗어날 때 입력값을, 페이지가 바뀌면 이동을 단계로 남깁니다.
   - 주소만 바뀌는 화면 전환(SPA, 해시 라우팅 `#/…` 포함)도 이동으로 남깁니다. 검색어처럼 쿼리만 바꾸는 주소 갱신과 페이지 안 앵커(`#section`) 이동은 남기지 않습니다.
   - 녹화 표시줄은 촬영 순간 잠깐 숨겨지므로 스크린샷에 찍히지 않습니다.
3. 녹화 바가 눌러야 할 버튼을 가린다면 **끌어서 옮기거나**, 바 오른쪽 **×로 아예 숨기세요.**
   - 옮긴 위치는 기억되고, 바를 두 번 클릭하면 오른쪽 아래로 돌아갑니다.
   - ×로 숨겨도 녹화는 계속됩니다. 다시 보려면 확장 아이콘 → **화면에 바 다시 표시**. 녹화를 끝내면 숨김은 자동으로 풀립니다.
   - 바가 없을 때도 툴바 아이콘의 숫자로 몇 단계가 쌓였는지 알 수 있고, 녹화 종료는 확장 아이콘의 **완료하고 편집**으로 합니다.
4. **완료하고 편집**을 누르면 편집기가 열립니다.
   - 확장 아이콘의 **기록 버리고 중단**은 이번 녹화를 가이드로 남기지 않고 스크린샷까지 지웁니다. 실수로 지우지 않도록 두 번 눌러야 실행됩니다.
5. 편집기에서 제목·설명을 고치고, 필요 없는 단계는 지우고, 가려야 할 영역은 드래그로 칠합니다.
6. **내보내기**에서 형식을 고릅니다.

### 편집기에서 할 수 있는 것

| 버튼 | 설명 |
|---|---|
| ↑ ↓ | 단계 순서 바꾸기 |
| 하이라이트 | 그 단계의 클릭 위치 테두리 표시 켜기/끄기 |
| 가리기 | 스크린샷 위를 드래그해 가리기. 설정의 가리는 방식(검정 칠하기·흐리게)을 따름 (ESC로 종료, × 로 해제) |
| 문장 복원 | 직접 고치거나 AI가 바꾼 문장을 자동 생성 문장으로 되돌리기 |
| 메모 단계 추가 | 스크린샷 없는 설명 단계를 끝에 추가 |

### 내보내기 형식

- **HTML 파일** — 이미지까지 한 파일에 들어간 self-contained 문서. 그대로 메일로 보내거나 사내 위키에 올릴 수 있습니다.
- **PDF로 인쇄** — 인쇄 창이 열립니다. 대상을 “PDF로 저장”으로 바꾸면 됩니다.
- **Markdown + 이미지 ZIP** — `guide.md` + `images/step-01.jpg …`. Notion·GitHub·Confluence용.
- **JSON** — 단계 메타데이터와, 하이라이트·가림을 구워 넣은 이미지(base64)를 담은 데이터. 다른 도구에서 쓰는 용도이고 다시 가져올 수는 없습니다. 옮기거나 보관하려면 아래 **전체 백업**을 쓰세요.

### 전체 백업과 가져오기

가이드는 이 브라우저의 확장 저장소에만 있어서, 다른 PC·다른 폴더로 옮기거나 확장 ID 가 바뀌면 보이지 않습니다. 옮기기 전에 전체 백업을 받아 두세요.

- **설정 → 데이터 → 전체 백업 내보내기**: 모든 가이드의 단계와 스크린샷 원본, 설정을 ZIP 하나(`clickguide-backup-날짜.zip`)로 받습니다.
  - 편집기에서 고친 문장·가림·하이라이트도 그대로 들어가서, 가져온 뒤에도 계속 고칠 수 있습니다.
  - AI API 키는 백업에 넣지 않습니다. 가져온 뒤 다시 입력하세요.
- **설정 → 데이터 → 백업에서 가져오기**: ZIP 을 고르면 들어 있는 가이드 수를 보여 주고 물어본 뒤 가져옵니다.
  - 같은 가이드(같은 id)가 이미 있으면 건너뜁니다. 같은 백업을 두 번 가져와도 겹치지 않습니다.
  - 설정도 백업의 값으로 바꿀지 따로 묻습니다. 바꿔도 지금 입력된 API 키는 그대로 둡니다.
  - 압축 프로그램으로 다시 묶은 ZIP 도 읽습니다. 내용이 손상된 파일은 가져오지 않습니다.

## 3. 설명 문장은 어떻게 만들어지나

기본은 **규칙 기반(오프라인)** 입니다. 외부 통신이 전혀 없습니다.

클릭한 요소에서 이 순서로 이름을 찾습니다:
`aria-label` → `aria-labelledby` → `<label>` → 버튼 value → 화면 텍스트 → `title` → `alt` → SVG `<title>` → `placeholder` → `data-testid` → `name`

여기에 역할(버튼/링크/체크박스/드롭다운/입력란…)을 붙이고 한국어 조사를 맞춰 문장을 만듭니다.

```
‘로그인’ 버튼을 클릭합니다.
‘이메일’ 입력란에 ‘hong@example.com’을 입력합니다.
‘국가’ 드롭다운에서 ‘대한민국’을 선택합니다.
```

**AI 다듬기(선택)** 를 켜면 이 문장을 LLM이 자연스럽게 고쳐 씁니다.
보내는 것은 단계 제목·설명, 동작 종류(클릭·입력·이동), 요소 이름과 종류(버튼·입력란 등)입니다. 설명 문장에 입력값이 들어 있으면 그 값도 함께 가고, 페이지 주소와 제목은 보내지 않습니다.
**스크린샷은 따로 체크하지 않는 한 전송하지 않습니다.** 체크하면 편집기에서 가린 부분을 적용한 이미지를 보냅니다.
AI 응답을 기다리는 동안 직접 고치거나 지운 단계에는 AI 결과를 덮어쓰지 않습니다.

### LiteLLM 연결하기

1. 설정 → AI 문장 다듬기 → 제공자를 **OpenAI 호환**으로
2. **LiteLLM** 버튼을 누르면 `http://localhost:4000` 이 채워집니다. 포트가 다르면 고치세요.
   - 주소는 **베이스 URL만 넣어도 됩니다.** `/v1/chat/completions` 는 자동으로 붙고, 실제 요청 주소가 입력칸 아래에 그대로 표시됩니다.
3. API 키에 LiteLLM 가상 키(`sk-...`) 또는 마스터 키를 넣습니다. 키 없이 뜬 프록시라면 비워 둬도 됩니다.
4. **목록 불러오기** 를 눌러 그 키로 쓸 수 있는 모델을 확인하고 고릅니다.
5. **연결 테스트** 로 확인합니다.

자주 걸리는 것:

| 증상 | 원인 | 해결 |
|---|---|---|
| `접근 거부(403) … team not allowed to access model` | 그 키의 팀에 허용되지 않은 모델 | **목록 불러오기** 로 허용된 모델을 골라 넣기 |
| `엔드포인트를 찾지 못했습니다(404)` | 경로가 틀림 | 입력칸 아래 “실제 요청 주소”가 `.../v1/chat/completions` 인지 확인 |
| `인증 실패(401)` | 키 없음/틀림 | LiteLLM 가상 키 또는 마스터 키 확인 |
| `… 에 연결하지 못했습니다` | 서버가 안 떠 있거나 포트가 다름 | `curl http://localhost:4000/v1/models` 로 먼저 확인 |
| 사내 서버인데 계속 연결 실패 | 평문 `http` 원격 주소는 브라우저가 막을 수 있음 | https 주소를 쓰거나 로컬에 프록시를 띄우기 |

Ollama는 **Ollama** 버튼(`http://localhost:11434`)을 쓰면 됩니다. 키는 비워 둡니다.

## 4. 개인정보 보호

- 가릴 곳은 **캡처 시점에** 이미지에 칠해 저장합니다. 원본은 남지 않습니다. 클릭 단계와 페이지 이동 단계 모두 같습니다.
  - 기본은 **검정 칠하기**입니다. 설정에서 흐리게로 바꿀 수 있지만, 흐리게 한 숫자(계좌·주민번호 등)는 원래 값을 되살리는 공격에 약합니다.
  - 0.2.0 까지는 흐리게만 했습니다. 이미 저장된 스크린샷은 그대로이고, 편집기에서 추가한 가림은 내보낼 때 지금 설정대로 칠합니다.
- 가리는 대상
  - `input[type=password]` 칸
  - 페이지 쪽에서 `data-clickguide-redact` 속성을 붙인 요소
  - 설정의 **항상 가릴 영역**(CSS 선택자)
  - 화면 글자와 입력값 속 **개인정보**: 주민·외국인등록번호, 카드번호(Luhn 검사), 사업자등록번호(검증 숫자), 휴대폰 번호, 이메일, 계좌번호. 계좌번호는 같은 칸이나 옆 칸에 '계좌'·'은행' 같은 말이 있을 때만 찾습니다. 설정에서 끌 수 있습니다.
- 가릴 곳은 클릭할 때와 **촬영 직후** 두 번 잽니다.
  - 그래서 클릭한 뒤에 뜬 모달이나, 클릭과 촬영 사이에 움직인 요소도 가립니다. 움직인 요소는 두 자리를 함께 덮습니다.
  - 녹화하는 탭의 **모든 프레임**(다른 출처 iframe 포함)과 shadow root 안까지 찾습니다. 닫힌 shadow root 는 웹 컴포넌트(이름에 `-` 가 든 사용자 정의 요소)에 붙은 것만 엽니다.
  - 어느 프레임의 가릴 곳을 확인하지 못하면 그 화면은 저장하지 않고, 편집기에 이유를 표시합니다.
- 개인정보처럼 보이는 입력값은 `●●●●` 로 기록됩니다. 주민·카드·계좌·휴대폰 번호, 이메일 모양의 값이거나, 12자리 이상 숫자이거나, 칸 이름이 `card`/`cvc`/`주민` 등인 경우입니다.
- 가리기 코드는 CleanShot Picker 와 함께 쓰는 공용 모듈(`src/shared/redact-core.js`)입니다. 원본은 저장소 최상위 `shared/` 에 있습니다.
- 편집기에서 드래그로 추가한 가림은 내보낼 때 이미지에 구워집니다. AI에 스크린샷을 보낼 때도 적용됩니다.
- 페이지 이동 단계의 문장에는 주소를 넣지 않습니다. 주소의 쿼리에 토큰이나 개인정보가 들어 있는 경우가 많기 때문입니다. 제목이 없는 페이지는 사이트 이름(호스트)으로 부릅니다.
- Markdown으로 내보낼 때 단계 문장 속 HTML 태그와 Markdown 문법(링크·강조 등)은 글자 그대로 나가도록 바꿔 씁니다.
- 녹화 스크립트는 **녹화하는 동안에만** 웹페이지에 들어가고, 녹화하는 탭에서만 동작합니다. 설정 중 AI 설정과 API 키는 웹페이지 쪽 스크립트에 보내지 않습니다.
- iframe 안에서 클릭·입력하면 내용은 확장 내부 메시지로만 전달합니다. 부모 페이지에는 내용 없는 일회용 표식 하나만 보냅니다(어느 iframe인지 찾기 위해서). 그래서 부모 페이지의 스크립트는 녹화 중이라는 사실과 클릭 시점은 알 수 있지만 입력값과 요소 정보는 볼 수 없습니다.

> 화면 전체를 찍는 도구입니다. 사내 시스템을 녹화하기 전에 보안 정책을 확인하고, 내보내기 전에 각 스크린샷을 한 번 훑어보세요.

## 5. 구조

```
manifest.json               MV3 매니페스트
src/
  background/service-worker.js   상태·탭 추적, 녹화 스크립트 등록/해제, 캡처 큐, 이미지 리사이즈·가리기, 저장
  content/recorder.js            클릭·입력·이동 감지, iframe 좌표 보정, 가릴 곳 재기, 녹화 표시줄 (녹화 중에만 등록)
  shared/redact-core.js          공용 가리기 코어: 개인정보 패턴, 보이는 영역 계산, 검정 칠하기 (CleanShot Picker 와 같은 파일)
  common/
    db.js          IndexedDB (sessions / steps / shots)
    settings.js    설정 스키마 + 기본값
    describe.js    규칙 기반 문장 생성 (한국어 조사 포함)
    render.js      하이라이트·가림 굽기, HTML/Markdown 빌더
    ai.js          선택적 LLM 연동
    backup.js      전체 백업·가져오기 (가이드·단계·스크린샷 원본 + 설정, API 키 제외)
    util.js, ui.css

```

동작 흐름:

```
pointerdown (녹화 대상 탭의 모든 프레임)
   → 요소 메타데이터 + 위치 수집
   → iframe이면 서비스 워커를 거쳐 부모로 올리며 좌표 보정 (iframe 테두리·안쪽 여백 포함)
   → 최상위 프레임: 녹화 표시줄 숨김 → 즉시 캡처 요청 (앞 요청을 기다리지 않음)
   → 백그라운드: 표시줄이 지워질 32ms 대기 → captureVisibleTab
   → 응답(촬영 시각 포함) → 표시줄 복구 + 그 시각의 좌표 표본으로 보정
   → 모든 프레임이 지금 가릴 곳을 다시 재서 보냄 (클릭 때 잰 것과 합침)
   → 리사이즈 + 가리기(검정 칠하기 또는 흐리게) → IndexedDB 저장 (촬영과 분리된 큐)

**속도를 위해 한 일**

- 녹화 중에는 백그라운드가 잠들지 않도록 붙잡아 둡니다(연결 포트 + 15초 신호). 잠들면 다음 클릭에서 콜드 스타트로 수백 ms가 날아갑니다.
- 상태와 설정을 메모리에 들고 있어 클릭마다 저장소를 읽지 않습니다.
- 클릭 요청을 직렬로 보내지 않습니다. 순서는 백그라운드가 메시지 도착 순서로 잡습니다.
- 촬영 전에 미리 기다리지 않습니다. 브라우저가 쿼터(초당 2회)로 막을 때만, 그것도 **남은 시간만큼만** 기다립니다.
- 쿼터에 막혔는데 그 사이 화면이 **전혀 바뀌지 않았다면** 방금 찍은 프레임을 그대로 씁니다. DOM이 조금이라도 바뀌었으면(모달이 뜨는 등) 반드시 새로 찍습니다.
- 가릴 영역이 없고 이미지가 충분히 작으면 다시 인코딩하지 않고 원본을 그대로 저장합니다.
- 표시줄이 지워지길 기다리는 시간도 메시지가 오가는 동안 이미 흐른 만큼을 빼고 남은 만큼만 기다립니다.

**더 빨라질 수 있나** — 남은 시간의 대부분은 브라우저 자체의 `captureVisibleTab` 호출(약 25~35ms)입니다.
설정의 **속도 진단**에서 이 PC·해상도 기준 실제 값을 잴 수 있습니다(재는 동안 같은 창에서 최근에 본 웹페이지 탭으로 잠깐 바뀌었다가 돌아옵니다). 여기서 '브라우저 촬영'이 100ms를 넘는다면
화면이 매우 커서 그렇고, 창을 줄이면 눈에 띄게 빨라집니다. 그보다 더 내리려면 `chrome.tabCapture`로
탭 영상 스트림을 받아 프레임을 뽑는 구조가 필요합니다(촬영 제한도 사라집니다). 다만 권한과 구조가 크게 달라집니다.

측정값 (1600×1000, DPR 2 기준):

| | 이전 | 현재 |
|---|---|---|
| 클릭 → 촬영 지연 (0.2초 간격 연속 클릭) | 최대 1,651ms | 최대 **128ms** |
| 화면이 멈춰 보이는 시간 | 최대 2,642ms | **40~110ms** |
| 백그라운드가 잠든 뒤 첫 클릭 | 느림 | **76~91ms** |
| 스크린샷이 빠진 단계 | 있음 | **없음** |
```

좌표는 실제 캡처 이미지 크기를 기준으로 **0~1 정규화**해서 저장하므로, 창 크기·DPR·DevTools 기기 모드가 달라져도 하이라이트 위치가 어긋나지 않습니다.

**클릭 시점과 촬영 시점의 어긋남 보정** — 버튼을 누르면 레이아웃이 밀리거나 모달이 뜨는 일이 흔합니다.
그래서 클릭 직후부터 매 프레임 대상 요소의 위치를 기록해 두고, 백그라운드가 알려 준 *실제 촬영 시각*에
가장 가까운 표본을 하이라이트 좌표로 씁니다. 촬영이 조금 늦어도 박스는 사진 속 요소 위에 정확히 놓입니다.
iframe 안에서 일어난 클릭도 같은 방식으로 보정한 뒤 좌표를 최상위 프레임 기준으로 변환합니다.
이 값은 부모 페이지의 스크립트가 볼 수 있는 `postMessage` 가 아니라 서비스 워커를 거쳐 전달합니다.

## 5-1. 녹화 바가 안 보일 때

확장 아이콘 → **녹화 시작**을 눌렀는데 화면 오른쪽 아래에 녹화 바가 뜨지 않는다면, 팝업이 이유를 알려 줍니다.

| 팝업에 나오는 말 | 뜻과 해결 |
|---|---|
| 브라우저 내부 페이지에서는 녹화할 수 없습니다 | `chrome://`, 확장 설정, 크롬 웹스토어 페이지는 브라우저 정책상 불가. 일반 웹페이지를 열고 다시 시작 |
| 페이지를 새로고침한 뒤 다시 시작해 주세요 | 확장을 다시 불러온 직후 열려 있던 탭. 지금은 자동으로 이어받지만, 실패하면 새로고침 한 번으로 해결 |
| 로컬 파일(file://)을 녹화하려면… | `chrome://extensions` 에서 이 확장의 **파일 URL에 대한 액세스 허용** 켜기 |
| 녹화할 웹페이지 탭을 찾지 못했습니다 | 창에 일반 웹페이지 탭이 없음 |

팝업에는 시작 전에 **어떤 탭을 기록할지**(`기록할 탭: example.com`)도 표시됩니다.

## 6. 알려진 한계

- Chrome 웹스토어 페이지, `chrome://` 페이지, 다른 확장의 페이지에서는 확장이 동작할 수 없습니다(브라우저 정책).
- `captureVisibleTab`은 **보이는 영역만** 찍습니다. 스크롤 아래 내용은 찍히지 않습니다.
- 브라우저는 화면 촬영을 초당 2회로 제한합니다. 그보다 빠르게 클릭하면, 화면이 그대로일 때는 방금 찍은 프레임을 재사용하고 화면이 바뀐 뒤라면 잠깐 기다렸다 새로 찍습니다. 그래도 많이 밀린 단계에는 편집기에서 경고가 뜹니다.
- 촬영에 실패한 단계는 편집기에 빨간 표시와 이유가 함께 나옵니다. 화면 표시줄의 깜빡임도 평소와 다른 색(주황)으로 알려 줍니다.
- 클릭과 동시에 사라지는 요소(모달 닫기 버튼 등)는 하이라이트를 자동으로 끕니다. 엉뚱한 자리에 박스를 그리지 않기 위해서입니다.
- 화면 개인정보 자동 찾기는 한 덩어리 글자 안의 번호만 찾습니다. 다음은 찾지 못하니, 꼭 가려야 하는 곳은 **항상 가릴 영역**에 넣거나 편집기에서 가리세요.
  - 태그로 나뉘어 표시된 번호(예: `010-<b>1234</b>-5678`)
  - 이미지·캔버스 속 글자
  - 녹화 스크립트가 들어갈 수 없는 프레임(`about:blank`, 샌드박스 iframe 등) 안
  - `div` 같은 평범한 요소에 붙은 닫힌 shadow root 안 (모든 요소를 열어 보면 큰 페이지에서 클릭이 굼떠집니다)
- 주문번호처럼 휴대폰·카드 번호와 모양이 같은 숫자는 함께 가려질 수 있습니다. 카드번호는 Luhn 검사, 사업자등록번호는 검증 숫자로 걸러도 우연히 맞는 번호가 있습니다.
- 녹화를 시작하기 전에 이미 열어 둔 다른 탭은 기록하지 않습니다. 기록할 탭에서 녹화를 시작하거나, 녹화 중인 탭에서 새 탭을 여세요.
- 하이라이트 좌표는 캡처 이미지 크기를 기준으로 다시 계산하므로, DevTools 기기 모드나 창 크기 변화에도 위치가 유지됩니다.
- 초당 2회 이상 캡처는 브라우저가 막습니다. 아주 빠르게 연속 클릭하면 캡처가 밀립니다.

## 7. 웹스토어에 올리려면

- 스토어가 확장 ID 를 따로 정하므로, 올릴 때는 manifest 의 `key` 를 빼야 합니다. 이 `key` 는 압축 해제 설치와 직접 묶은 CRX 배포에서 ID 를 고정하려고 넣은 것입니다. CRX 를 직접 묶을 때 쓰는 개인 키(`.pem`)는 저장소에 올리지 않습니다(`.gitignore`).
- 심사에서 `<all_urls>` + `tabs` 권한의 **사용 목적 설명**을 반드시 요구합니다. “사용자가 명시적으로 녹화를 시작한 탭의 화면을 캡처해 매뉴얼을 생성” 으로 기술하세요.
- 개인정보처리방침 URL이 필요합니다(원격 전송이 없다면 그 사실을 명시).
- `activeTab` 만으로 좁히려면 녹화 시작 시마다 사용자 제스처가 필요해 페이지 이동 후 캡처가 끊깁니다. 지금 구조는 `<all_urls>` 를 전제로 합니다.
